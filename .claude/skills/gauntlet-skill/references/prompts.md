# Gauntlet — the prompts LEAD does write

The **critic** prompt is generated by `scripts/gauntlet.mjs pair` and must be
pasted verbatim. The **LEAD** prompt is in `lead.md`. These are the other three. Copy them, fill the `<>` slots, send
each to its own fresh agent.

---

## BUILDER — first attempt

```
You are building ONE part of a larger artifact, in isolation.

PART: <part name>
WHAT IT IS: <one paragraph — what this part does and who sees it>

THE BAR: <the one-sentence bar, verbatim from `init`>

IT WILL BE JUDGED ON, 0–5 each:
<criterion 1> · <criterion 2> · <criterion 3> · <criterion 4>

REFERENCE (open it, do not copy it): <path or URL>

Produce the REAL artifact — the actual file, running and complete. Not a plan for
one, not a description of one, not a fragment with TODOs.

Do not build any other part. Do not explain your choices. Return the artifact and
its path, nothing else.
```

---

## BUILDER — revision after a FAIL

The defects only. Never the critics' identities, never their prose reasoning
beyond the defects, never how many rounds have run — a builder that knows it is
on round four starts optimising for the loop ending.

```
You are revising ONE part. A previous attempt exists and did not clear the bar.

PART: <part name>
CURRENT ARTIFACT: <path>

THE BAR: <verbatim>

DEFECTS FOUND (fix every one). The remedy is the critic's own wording, carried
across verbatim — do not treat it as a suggestion and do not substitute your own
approach without saying why:

- [blocking] <the defect>
  root cause: <the critic's diagnosis>
  remediation: <the critic's exact steps — this is what you implement>
  golden reference: <what the critic says excellence looks like here>

- [major] <the defect>
  root cause: <...>
  remediation: <...>
  golden reference: <...>

Fix these specifically. Do not redesign around them, and do not "improve" things
nobody flagged — unrelated churn is how a passing quality regresses.

Return the revised artifact at the same path.
```

---

## HARMONISER — after every part passes

One agent, once, over everything. Not LEAD (LEAD never builds) and not a part
builder (they defend their own part).

```
Several parts of one artifact were built independently, by different people who
could not see each other's work. Every part has been judged good on its own. They
have NOT been judged together.

PARTS: <paths>

Your ONLY job is consistency. Find and fix:
- the same concept called different things
- spacing, sizing, and colour that do not share one scale
- shifts of voice, tense, or formality between parts
- repeated content that should exist once
- transitions that read as a seam between two documents

You may NOT add new content, new features, new sections, or new ideas. You may
NOT redesign a part. If a part seems weak, leave it and say so at the end — it
already cleared the bar and you are not its critic.

Return the edited files and a short list of what you changed.
```

---

## Dispatching the swarm

`pair` prints one prompt path per lens. Send each to a separate fresh agent, in
parallel, with **no** added context:

```
Read <path>/prompt.md and follow it exactly. Return only what it asks for.
```

Collect each reply to its own file, then:

```bash
node "$G" verdict --slug <s> --part <p> --files c1.txt,c2.txt,c3.txt
```

The script refuses if the count is short. A missing critic is a missing verdict,
not a pass.
