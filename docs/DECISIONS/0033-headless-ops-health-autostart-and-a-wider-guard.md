# ADR 0033 — Headless operations: health, autostart, and a wider credential guard

- **Status:** Accepted
- **Date:** 2026-08-18
- **Extends:** ADR 0030 (the headless Mac), ADR 0012 (the Hive), ADR 0029 §5
- **Delivers:** punchlist items 4, 5, and 8 from `docs/PICK-UP-HERE.md` §6-B

## 1. `npm run health` — the local half of "a silent node is loud"

ADR 0030 §1b: on a machine nobody opens, health reporting is the ONLY way
anyone finds out something broke, and it must exist before anything depends on
the Mac being up. This ships the half that can be built without a decision from
William:

Six checks, each returning a verdict and a one-line detail: node version,
commits behind the last-fetched remote (deliberately no network — a health
check that needs the internet reports the internet, not the machine),
dependencies linked, the database file present with a real SQLite header
(driver-free on purpose: it answers "is the file there and not garbage",
and does not pretend to answer whether the schema migrates — only launching
the app proves that), `.env` key **names only**, and free disk. Non-zero exit
if any check fails, so launchd logs and scripts read the verdict without
parsing prose. **A health report is designed to be pasted, so it must never
contain a secret value** — tested with a planted value that must not appear.

**What this is NOT (stated, not implied):** the remote half — a report whose
ABSENCE a phone notices. That needs a push channel, and choosing it (email?
text? which recipient?) is William's, recorded as blocked-on-William in
`docs/PICK-UP-HERE.md`. Until then the interval log means that when something
breaks unattended, the evidence is already written down — which beats
reconstructing it and is honestly less than being told.

## 2. `npm run install:autostart` — Jarvis starts itself

Two LaunchAgents, generated by a pure, unit-tested builder:

- **`com.jarvis.desktop`** — `RunAtLoad` + `KeepAlive`, running
  `npm run dev:awake` (the app plus `caffeinate` — a head node that sleeps is
  down). If it dies, launchd restarts it.
- **`com.jarvis.health`** — `npm run health` every 30 minutes, appending to
  `~/Library/Logs/Jarvis/health.log`.

Choices worth recording:

- **LaunchAgents, not LaunchDaemons.** The app needs the logged-in user's
  session — a window server, the keychain, `~`. The cost is honest and stated
  by the installer itself: a reboot stops at the login screen unless the
  account is set to log in automatically, which is a System Settings step only
  a human at the machine can perform once.
- **npm by absolute path.** launchd's minimal PATH knows nothing of nvm or
  homebrew — the classic agent that works in a terminal test and never at
  login. Pinned by test.
- **Refuses off-macOS** rather than no-op'ing, the ADR 0016 rule: a CI that
  "verified" an installer that installs nothing would be the exact green-but-
  false signal this repo keeps hunting down.

**Status: `IMPLEMENTED, NOT YET VERIFIED`.** The plist content is unit-tested;
no macOS machine has run the installer. It becomes verified when William runs
it on the Mac and a login starts Jarvis.

## 3. The credential guard learns four more shapes

ADR 0029 §5's guard caught six vendor key formats while its refusal copy said
"API key or password". The gap list named what fell through; four families are
closed: AWS access key ids (`AKIA`/`ASIA`), Slack tokens (`xox[baprs]-`), JWTs
(two `eyJ` base64url segments joined by a dot), and connection strings carrying
a real password (`scheme://user:secret@` with an 8+ character secret — the
length floor deliberately excludes the documentation placeholder
`user:pass@host`, so prose ABOUT the guard does not trip the guard).

Widened in lockstep in all THREE copies — `scripts/lib/secret-scan.mjs`, the
memory guard, and the Gauntlet skill's portable scanner — which the two
agreement suites force: widening one alone turns CI red.

**Still not caught, still stated:** a bare password, an account or card
number, a personal note. The file-choice gate (`whyNotReviewable`) remains the
defence for those, and `docs/KNOWN-LIMITATIONS.md` keeps saying so.
